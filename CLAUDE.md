# Mine World — command center

Open-world incremental minesweeper (web + Electron). Design spec: [minesweeper-incremental-spec.md](minesweeper-incremental-spec.md). Read the spec's §1 invariants before touching `packages/core`. The spec's `▶ 구현` blocks and §17 record where the implementation confirmed or changed the design; keep them in sync when behaviour changes.

Status (2026-09-22): Phases 0–4 implemented + bases + title screen; game cut down to the incremental basics (main-base level, streak cap, mining tiers; no solver-tier automation, drones or consumables for sale); point economy (tiles +1, bases +5, × base multiplier × combo, into a capped pool that must be cashed out; bases produce nothing); mine blasts disable bases; terrain walls (mountains, rivers) force guesses; fog of war (fixed vision: main base, bases, opened cells); the first click places the main base on fog; mining tiers gate expansion; "?" marks; floating capsule HUD and top-right popovers (no status bar, no log / stats UI); Earth mode (the real world map, wrapping east-west), played online only: Earth multiplayer through a Node WebSocket server (shared live board, signature colours, private flags, score + session scoreboard, a mine is game over); 84 core tests green, Phase 1 manual play-test still to do.

Code, comments and docs are English; the UI is Korean + English (i18n in `packages/web/src/i18n.ts`).

## Commands (repo root)

```
npm install
npm run dev            # web client at http://localhost:5173
npm run server         # Earth multiplayer server on :8787 (the dev client connects to it; builds use VITE_MINE_SERVER); start-server.bat does the same on Windows
npm run electron:dev   # Vite dev server + Electron window
npm test               # core invariants (vitest)
npm run sim            # Phase 0 measurements (~3-5 min); add -- --quick for a short run
npm run typecheck      # all packages
npm run build          # packages/web/dist (a push to main deploys it to https://toniqat.github.io/mine-world/ via .github/workflows/pages.yml)
```

Visual check without a human: build web, then in `packages/electron` run `npx electron . --exec=script.js --screenshot=out.png` (see its README; clear `ELECTRON_RUN_AS_NODE` if an IDE terminal set it).

## Decisions taken while implementing (deviations / refinements of the spec)

- **Consistency model.** The world's `truth(x, y)` (override ?? stateless base ?? frozen per-chunk debt pressure) is always a full assignment consistent with every revealed number. Safe reveals are therefore *not* committed (keeps overrides sparse, §3.2); only interventions, hits, scanner cells and probes write overrides. Interventions commit a whole alternative solution of the component (the spec's "optional optimisation" is mandatory for consistency). See `packages/core/src/world.ts` and `resolve.ts`.
- **Settlement unit = claim batch, not CSP component.** Flags in public mode chain through the whole frontier, so "component closed" almost never happened at ≥30 % density. A flag is settle-able once every revealed number next to it is sealed; settle-able flags linked through shared sealed numbers form one batch. Feedback still only happens at settlement (INV-2).
- **Only openings settle.** A flag action never settles anything (placing a flag does not turn flags into bases on the spot); its cells are remembered (`Game.deferred`, saved) and the next opening anywhere settles whatever became settle-able around them.
- **Chords are never rescued.** Reveals made by a chord skip FAIR / FORGIVING intervention (`resolveReveal(..., rescue = false)`): a chord trusts the flags, so a wrong flag lets the real mine go off.
- **Wrong flags are punished. A batch with any wrong flag forfeits all of its real mines (`CellState.Lost`), pays nothing, and burns a fraction of unbanked funds. Without this, flagging everything would be a free probe.
- **Mine hit = resource loss (Sapper-style), no HP.** Points land in *unbanked* funds (the pool) with a click-streak (combo) multiplier; stepping on a mine burns `mineHitLossFraction` of it; **Cash Out** banks it. See *Point economy*.
- **Six solver tiers instead of four.** Phase 0 showed T1 alone producing 70–93 % of verdicts, so T1/T2 are split: T1a open, T1b flag, T2a subset, T2b overlap (no chained derived constraints), T3 enumeration ≤ 32 cells, T4 enumeration ≤ 48 cells + probabilities. They are no longer sold (see *Incremental basics only*); drones use whatever tiers their equipment grants.
- **Zero-cascades are bounded** (`play.cascadeRadius` / `cascadeCap`) because low densities percolate forever.
- **Density debt** is repaid by freezing a per-chunk pressure the first time a chunk is observed, which keeps truth stable without commits.
- **Drones are dormant.** Nothing in the game creates drones now; the logic stays for planned equipment items, which will go through `Game.equipDrones(loadout)` (count, tiers, radius / speed levels, safe mode; saved as `SaveData.droneLoadout`). The rules below still describe them. **Drones stand on Owned mines.** A new drone auto-places on a free Owned mine with a lot of Unknown around it; the player can drag it to another one (it pauses while held). Each action extends a line tile by tile to the target (`baseMoveTilesPerSec`), then fills `acc` and executes; the next target is the one nearest the line's end (`tip`) and the line continues from there instead of retracting to the anchor (reset to the anchor on stall, hop, drag or placement). When its tile-rounded disc (`inDisc`) has nothing determined it rides a line to another Owned mine, leashed to the radius of the mine it was placed on (reach ≤ 2r); otherwise it stalls (red). The old follow-the-player assistant is gone.
- **The world starts all fog; the first click places the main base.** Nothing is opened for the player and every cell is fogged. The first click is a main-base placement, allowed on fog: that cell becomes the main base, the centre of the mine-free start area, the distance ramp and the tier rings, and the start area opens (`World.setStart`, locked once any truth is observed, saved in `SaveData.world.start`). The map (biome, mines, terrain) is read in coordinates relative to the start (`world.startRelative`), so where the player clicks does not matter: placing is effectively a start button. Saves without `startRelative` keep absolute maps. Home (`H`) goes there.
- **Clicking a number presses its neighbours.** Its Unknown neighbours that can be acted on (not fogged or locked) and stay closed after the chord shrink and spring back (`BoardView.press`).
- **Over-flagged numbers turn red.** A number with more flags and known mines (bases, exploded, lost) around it than it says is drawn in the error colour at full strength.
- **Finished numbers disappear.** A number with no Unknown neighbour dims to 25 % opacity while an unsettled flag is still next to it, and fades out once none is; opened tiles flip over (the cover folds away, then the number unfolds) in a ripple from the clicked cell (a cascade's start, `CellChange.from`, or the chorded number); fog lifting fades in a ripple from the clicked cell (the first click: outwards from the new main base; the start area comes out of the fog as closed tiles and only flips open once the whole fog lift has finished).
- **Bases.** Every Owned mine is a base (거점, small dot); the start cell is the main base (주 거점, large diamond). Bases produce nothing (see *Point economy*); each main-base level raises the pool cap. Bases form a tree rooted at the main base with no range limit: a base's next hop is the nearest base (Manhattan) that is closer to the main base. Edges are 4-neighbour tile paths that never cross an Unknown or flagged cell; terrain walls count as opened (shortest by BFS, preferring straight runs), drawn a sixth of a tile wide at ~10 % opacity. Shipments along the network are only a picture of the link: each linked complex keeps sending one every `shipIntervalSec` (2 s) on its own clock (phase from its hub), turns or not, moving at `transportTilesPerSec` and carrying nothing; they fade as the view zooms out below 60 % and are not drawn below 35 %. The `transport_speed` upgrade is gone. No link bonus. Only the main base is levelled (`packages/core/src/econ/bases.ts`, `config.bases`). Clicking a base lights it up (a soft light behind it, its icon a little larger) and highlights its route; there is no panel for ordinary bases. A disabled base also shows a modal speech bubble with its Repair button (a press anywhere else only closes it). Clicking the main base and the HUD main-base button (top right, where home used to be; `H` still goes home) toggle the main-base popover (stats, the next level with a Level up button under it, then one upgrade list including the mining technology; costs shown inside the buttons; no close button, a press outside closes it and still acts). A base is *settled* when its 8 neighbours hold no Unknown / flag and every number among them has faded out; settled bases within 2 tiles (Chebyshev, chained) form a **complex** that acts as one network node (instant inside; the main complex pays at once; drawn with a faint round-cornered border); an unsettled base is a complex of its own. A complex with no such path to the main complex is **isolated** (translucent, not counted, no link) until a way opens. A complex of ≥ 5 bases is a **grand complex**: members count ×(1 + 0.05 × members) towards the multiplier (`grandMinBases`, `grandBonusPerBase`); forming one plays an effect at its centre (`grand` event). Every new base shows the points it earned rising from its tile. A shipment that arrives leaves its trail fading in place; inside a complex of two or more bases shipments are not drawn, so goods appear to leave and enter through its border.
- **Mine blasts disable bases and lift flags (chain reactions).** Stepping on a mine (still burning unbanked funds) sets off a circular blast centred on it. Its radius is rolled uniformly in the range of the mine's mining tier (`blast.radiusByTier`: 2.1–3.5 in tier 1 up to 3.5–4.9 in tier 5, cut ~30 % on 2026-09-22). The effect flashes every tile inside the blast in a wave from the centre (no ring). Every base inside is **disabled**: not counted and not a base for complexes or the network. The main base is immune. Every flag inside is lifted; a flag that sat on a mine goes off too (`CellState.Exploded`, not repairable) and blasts in turn (`BlastEvent.chain`, drawn when the earlier wave reaches it); only the first mine burns funds. What a blast shows is committed to the world (mine 1 / lifted flag 0). A disabled base is repaired from the bubble that clicking it opens, for `repairCostBase + repairCostPerTile × opened cells` credits (`packages/core/src/econ/blast.ts`, `config.blast`).
- **Terrain walls force guesses (reverses spec §0.4 claim 3).** Mountains and rivers are cells with no tile, no mine and no number (`CellState.Mountain` / `Water`, never stored: `Board.terrain` -> `World.terrain`, stateless from seed + start cell, none before the start is set or within `terrainMinRadius`). The CSP treats them as known safe in every mode, like a finite board's edge, so ambiguities pinned against them cannot be bypassed. FAIR never rescues a pocket whose flood fill touches a wall. Rivers are broken by fords so they never enclose an area. Walls count as resolved for base settling and as opened cells for the network, so a base walled in by terrain still links (user decision 2026-09-22). The old mine-band river is gone; saves without `terrainEnabled` load wall-free with their old rivers. Scanners to buy information against these guesses come later.
- **Fog of war.** A closed cell (Unknown, flag or wall) no vision source has seen is fogged (everything before the start): drawn as a faint tile with a dashed outline (mountain and river look the same), and it cannot be opened, flagged or chorded into. Sources, all with fixed radii (no growth): the main base (disc `mainRadius` 16), every base (disc `baseRadius` 9, at once) and every opened cell (square `openedRadius` 2, so cascades never run into fog). Fog never returns and follows from the sources alone, so it is not saved (rebuilt from bases and opened cells on load; tuning always from the current defaults). `packages/core/src/fog.ts`, `config.fog`; tests and the sim turn it off.
- **Mining tiers (tech tree).** Rings around the main base: tiers 2 / 3 / 4 / 5 from 24 / 48 / 88 / 128 tiles (Euclidean, `config.tiers.radii`; the old 48 / 128 rings split in half). Tier 1 is always minable; tier n needs the single levelled technology `mining` at level n − 1 (upgrade group `tech`, max level 4), bought in the upgrade list of the main-base panel. Its price table (`costs`: 10k / 150k / 1.5M / 6M) is about half of what the tier below pays in points (estimated, not simulated; TODO(play)). Old saves' `mining_t<n>` become `mining` level n − 1. A locked cell cannot be opened, flagged, marked or chorded into, and cascades stop at it (`Game.tierAt` / `miningTier` / `locked`). Higher-tier mines blast wider (the value multipliers went with the point economy). Tiles are not tinted per tier: every locked tile shares one colour (`cellLocked`) and a padlock, and turns into a plain Unknown tile once its tier is unlocked. Each level emits `tech`. Tests and the sim turn tiers off except `tiers.test.ts`.
- **Incremental basics only (for now).** Upgrades are the main-base level (header of the main-base panel), `streak_cap` and the mining technologies. Solver-tier automation, drones and consumables (audit, scanner, probe) are not sold and the probability overlay is gone; scanner / probe / audit stay as core methods with a caller-given price. Older saves drop the retired upgrades and their drones; base / blast tuning always comes from the current defaults.
- **"?" marks.** Right-click (or flag mode, or a tap on touch devices) cycles Unknown -> flag -> "?" -> Unknown (`Game.cycleMark`). A "?" is only a note: the cell stays `CellState.Unknown` for every rule (opens, chords, cascades, never settled); marks live in `Game.questions` (saved as `SaveData.questions`) and vanish when the cell changes state.
- **Title screen.** Shown on every launch: MINEWORLD (top centre), two mode buttons of the same size side by side (bottom centre): single player (the endless world) on the left, multiplayer (Earth) on the right. A mode with something to go back to says Continue (a save; a kept seat) and has a small New game under it: single keeps cores after a confirm, multi gives up the kept seat at once after a confirm (`hello.leave`: the old player leaves, their land stays uncoloured) and joins a new session. There is no long press anywhere (removed 2026-09-22, and its setting with it). Behind it a throwaway, never-saved world is played by a small bot (`packages/web/src/demo.ts`: digs a corridor from the start along one heading per world (left or right, slightly tilted) with every solver tier, one action every ~0.44 s, least likely mine when stuck; three guesses in a row, nothing left in the corridor or 500 actions ends the world: fade out, black, the next world fades in; zoom 75 %, the camera glides one way after the dig front with eased speed, never sideways or back) under a film layer (grain, scanlines, vignette, faint flicker, the grain and flicker on random timers so nothing wobbles on a beat; no REC label or timecode). Start slides the logo up and the buttons down while they fade, the demo fades out, then the player's world appears tile by tile in a diagonal wave from the top-left of the screen (`BoardView.intro`); HUD and input come back after. A world with no main base yet shows a "click anywhere to found the main base" hint until the first click. The demo world runs with mining tiers off.
- **Point economy (2026-09-22).** Bases no longer produce. Every cell an opening reveals earns `econ.tilePoints` (1) and every base a settlement creates `econ.basePoints` (5), × `Econ.pointMult()` = base multiplier (1 + `multPerBase` 0.1 × linked, non-disabled bases, grand members weighted by their bonus; from the last network rebuild) × combo × prestige, into the unbanked pool. The pool holds at most `storageBase × storageGrowth^(main-base level − 1)` (1k × 1.5^(L−1)); while full, `reveal` / `chord` open nothing (`RevealResult.full`) and the player must Cash Out; flags still work. Density and tier value multipliers are gone (density only feeds prestige). Tests and the sim run with `storageBase: Infinity`, as does the title demo.
- **HUD and popovers (2026-09-22).** No top bar and no bottom status bar: floating capsules (pool with cap bar and Cash Out, then combo × multiplier in its own capsule, top centre; credits, then flag mode / main base / settings top right, the open popover's button in a blue circle). The home, log and stats buttons are gone, and so are the log, stats and liquidation UI (core keeps the log and `liquidate`). Settings and the base panel open as a rounded popover under the top-right capsule. Popovers and dialogs drop in from a little above while fading in. The shown credits and pool count unit by unit towards the real values, faster for bigger gaps; pool changes float up as one +N / −N per action, a combo broken by a mine or wrong flag floats up as −N from the combo, and a Cash Out drains the pool into credits. Mine hits show no toast.
- **Touch devices (2026-09-22).** A device with a coarse primary pointer (`packages/web/src/device.ts`) plays by touch: tapping a number chords, tapping a closed tile cycles flag -> "?" -> clear and never opens it (tiles open only through chords; the first tap still places the main base), two fingers pinch-zoom; no flag mode. Phones get a two-row HUD (credits + buttons, then pool + combo).
- **Earth mode (2026-09-22).** A second world, played from the title's multi button, now online only (see *Earth multiplayer*; the old single-player 'earth' save slot is no longer read): `WorldConfig.map = 'earth'` reads the world from a land mask of the real continents (`packages/core/src/maps`, 1440 × 720 cells of 0.25°, equirectangular, generated from Natural Earth 1:50m land by `packages/core/scripts/earth-mask.mjs`; continent outlines only: small islands dropped, small lakes filled). Water, and every row above or below the map, is a `Water` wall from the start (no procedural mountains or rivers); coordinates are absolute (not start-relative), so the first click chooses where on Earth the main base goes, and water refuses it. The map **wraps east-west**: core keeps every stored or keyed column canonical (`wrapX`, `deltaX`; `World.wrap`, `Board.wrap`, `Fog.wrap`, `Bases` wrap, `Game.wx`; `forEachNeighbor(x, y, fn, w)`), so neighbours, cascades, chords, blasts, tiers, fog, complexes and network paths all work across the 180° seam; drones (dormant) are not wrap-aware yet. The biome noise is not periodic, so density jumps at the seam (Pacific / Chukotka / Antarctica). Fog of war is unchanged, but fogged water shows as a faint wash so the coastlines are visible. The client wraps the camera, draws the board a second time a world-width to the side where the view crosses the seam (`BoardView.renderSeam`), may zoom out until the whole Earth fits (below zoom 0.2 an `Overview` texture of one texel per cell replaces the tiles), and is look-only below zoom 0.5 (the zoom where numbers stop being drawn; Earth mode only). A fresh Earth world opens zoomed out on the whole map.
- **Earth multiplayer (2026-09-22, user decisions).** The Earth map is always played online, against an authoritative Node WebSocket server (`packages/server`) that runs one core `Session` per session (`packages/core/src/multi`); the client mirrors it in a `MirrorGame` (a `Game` whose board the server writes; openings and chords are only sent). The endless world stays single-player with every rule above; everything below applies to Earth only.
  - **Sessions.** Start picks a random signature colour (12, `SIGNATURE_COLORS`) and a random session with fewer than 12 players (`MULTI.maxPlayers` 11) and under 90 % of the land opened (`joinMaxUnlock`); none: a new session (new seed). A player offline for 10 min (`idleKickMs`) leaves; their land stays, uncoloured. The browser keeps a token to rejoin (the multi button says Continue), dropped on game over; the New game under it leaves that seat at once. Sessions are saved as JSON on the server (`DATA_DIR`).
  - **Removed on Earth:** base links, complexes and grand complexes, upgrades (main-base level, streak cap, mining technology), tiers, combo, pool / Cash Out and credits, fog of war (`multiConfig`). Points go straight to the **score**: +1 per cell an opening reveals, +5 per base a settlement creates, −5 per wrong flag (the batch still forfeits its mines).
  - **Shared board, private flags.** Every opened cell and base belongs to its opener (`OwnerLayer`) and is drawn tinted with their colour; everyone sees digging and blasts live. Flags and "?" marks are per player (never on the shared board; the server keeps flags for settlement). A number is sealed for a player when every closed neighbour carries one of their flags, whoever opened the number; chords count only their own flags. Opening a cell drops anyone's flag on it.
  - **A new base takes the land around it.** When a player's flag settles into a base, every opened cell among its 8 neighbours becomes theirs, other players' land included (`Session.claimAround`; another player's main base, bases and lost mines stay whose they are). Each cell taken scores +1 for the taker and −1 for its former owner (none for land nobody owns).
  - **Main base.** The first click needs untouched land: nothing opened within `startRadius + 1` (3) tiles and no committed mine in the square; the square of `startRadius` (5 × 5) is committed mine-free (the mines removed go to density debt), so every start opens a patch. No start-centred density ramp or safe radius on Earth.
  - **A mine is game over.** The blast is shown to everyone but touches nobody else; every cell the player owned (land, bases, lost mines, their main base) turns back to Unknown (the mine stays where it is, committed), the player leaves the session, and the client shows the final score and returns to the title.
  - **Colours.** Online the theme's accent is replaced by my signature colour (flags, selection, the chrome's `--accent`); land nobody owns any more is drawn plain with muted bases. Top right: my score next to the buttons, the session scoreboard under them; clicking a player there (me included) moves the camera to their main base.
- **Prestige A (liquidation)** (no UI at the moment).

## Conventions

- Every package folder has a README describing its files; update it when files change.
- Core never imports from web/electron. Web talks to core only through `Game` methods and `game.events`.
- Tests: `packages/core/test`. Keep the invariant tests green before merging core changes.
